# 资源导入模板与卡记录完整性

## 目标

账号、卡、地址的导入抽屉都提供与其导入规则一致的下载模板。卡记录保持行级或对象级原子性，避免卡号、有效期、CVC 跨行或跨文件拼配。

## 模板

- 账号：下载 `accounts.json`，包含一个待填写的 `accessToken` 与 `user.email` 结构。
- 卡：下载 `cards.csv`，仅含 `number,exp,cvc,name` 表头。
- 地址：下载 `addresses.csv`，仅含 `line1,city,state,zip,country` 表头。
- 模板在导入抽屉内容区顶部、文件选择按钮之前；下载不向服务端发送数据。

## 卡导入规则

- CSV 的每一行、TXT 的每一行、JSON 的每一个对象均是一张卡的完整记录边界。
- 只接受已定义字段和固定的 TXT 管道分隔格式；不从说明文本、日志或相邻行推断字段。
- 卡号只允许数字、空格和短横线格式化，标准化后必须通过 Luhn 校验。
- 有效期必须为未来的 `MM/YY` 或 `MM/YYYY`；CVC 必须为 3 或 4 位数字。
- 任何字段不完整或校验失败的行不入库，错误只返回行号和通用原因。

## 验收

1. 三种导入抽屉均显示其专属模板下载入口和正确文件名。
2. 下载内容不含真实账号、卡、地址或凭据。
3. 有效格式化卡号通过；Luhn 不合法或混入字母的卡号被拒绝。
4. 已有资源导入、脱敏列表与选择行为不回归。
