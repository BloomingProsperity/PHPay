# HTTP/HTTPS 代理与支付资源调度设计

## 已确认的部署边界

- 系统可以有多个 Docker 部署。
- 每个部署独立使用自己的账号库、卡库、地址库、代理池和任务目录。
- 不同部署之间不共享资源，因此不需要 Redis、PostgreSQL 或跨主机分布式锁。
- 本设计中的锁、游标、健康状态和等待队列都只属于当前部署。
- 若以后改成共享资源池，替换租约存储实现即可，支付阶段状态机不需要重写。

## 目标

在不增加新 Docker 服务、不执行真实支付测试、暂不修改 TLS 指纹策略的前提下，完成以下能力：

1. 批量运行前并发预检代理，跳过当批不可用代理。
2. 账号、卡、持久地址和代理从上到下顺序分配，不随机选择。
3. 代理、卡和持久地址使用硬租约；未来指纹使用软租约。
4. 资源不足时只降低实际并发并排队，不拒绝整批。
5. 根据支付是否进入不可逆阶段决定能否更换卡、地址或代理。
6. 3DS 和结果未知任务不得自动重复提交支付。
7. 移除 250ms 文件扫描等待，改为资源释放事件唤醒。

## 性能原则

- 不引入数据库、消息队列或后台守护服务。
- 每批只创建一个轻量协调器和有限数量的 Promise 等待者。
- 代理预检并发执行，使用统一超时；测试结果只作用于当前部署和有效期。
- 卡和地址在批次开始时生成稳定顺序快照，运行时依靠原子 `reserve` 再确认。
- 资源释放后主动唤醒等待任务，不定时扫描整个资源目录。
- 所有重试都有明确类别和有限资源集合，不允许无限重试。

这里的“性能”主要指账号从导入识别到成功支付的端到端耗时，而不是 Docker 构建或启动耗时。正常支付主链路应优先减少网络往返：

1. 账号导入后的 token 解析和状态检测结果在当前部署内短时复用。
2. 同一账号已有检测请求执行中时，付款流程等待同一个 Promise，不再发起第二次检测。
3. 新鲜状态结果只作为本次付款前置判断；过期、凭证变化或上次检测失败时重新检测。
4. 创建结账会话后，PaymentMethod、Stripe init 和 Sentinel 三个互不依赖的请求并行执行。
5. approve 完成后立即做第一次支付状态查询，只在后续查询之间等待。
6. 代理检测和账号检测尽可能并行，不把整池代理检测串联到每个账号前面。
7. 支付关键阶段记录耗时，便于定位真正变慢的外部请求，但不记录凭证、卡号或代理密码。

### 当前部署内的短时账号上下文

内存缓存以账号资源 ID 和凭证摘要为键，保存：

```text
resolvedToken
email
accountStatus
checkedAt
inFlightPromise
```

- 缓存不写入磁盘，容器重启后自然失效。
- 导入后立即开始的状态检测会填充缓存。
- 支付请求遇到同一账号的检测正在执行时复用该请求。
- 成功状态结果默认有效 120 秒；失败和凭证无效结果不作为快速支付缓存。
- 用户手动重新检测、账号删除/清空或凭证变化时清除对应缓存。
- 每个 Docker 部署拥有自己的缓存，不跨部署共享。

## 代理池

### 支持格式

- `http://host:port`
- `https://host:port`
- `http://user:password@host:port`
- `https://user:password@host:port`
- `host:port`
- `host:port:user:password`

仅支持 HTTP/HTTPS。代理密码只保存在当前部署本地配置中，公共 API、日志和 UI 必须脱敏。

### 批量预检

批量运行创建账号任务前：

1. 获取代理池稳定快照。
2. 复用最近 120 秒内的健康结果；只重新测试未知或过期代理。
3. 使用现有 `testAt` 并发测试待检查代理，并发上限为 `min(批量并发数, 10)`。
4. 每条代理测试最长 4 秒；超过时限视为本批不可用。
5. 某条代理一旦检测为健康即可参与第一波任务，不等待其他代理全部完成。
6. 测试失败只标记当前运行期，不永久删除或禁用代理。
7. 无代理配置时返回一个不需要加锁的“直连”网络上下文。

预检结果必须包含脱敏状态统计，但不能向公共 API返回原始代理。

### 硬租约与顺序游标

- 每次批量从代理池顶部开始。
- 从当前游标向下查找健康且未占用的代理，到底后回到顶部。
- 一个代理同一时刻只允许一个支付任务使用。
- 释放后唤醒排队账号，游标继续向下移动。
- 同一个账号的安全重试保持任务序号，但允许在明确的提交前代理故障后取得下一条代理。
- 已提交支付的任务不得换代理重新提交。

## 卡、地址和未来指纹

### 卡

- 卡使用现有持久化硬锁。
- 依次跳过使用中、冷却中、余额不足和格式无效的卡。
- 明确未扣款的卡错误可以换下一张卡。
- 余额不足的卡暂停使用，直到用户恢复。
- 支付成功后卡释放，并冷却 30 秒。
- 提交支付后结果未知时继续锁定卡，禁止换卡重付。

### 地址

- 持久地址使用现有硬锁。
- 导入和批次准备阶段检查必填字段以及可验证的格式组合。
- 没有空闲持久地址时生成本次临时地址，不阻塞账号。
- 平台在支付提交前明确拒绝地址时，标记该地址本批不可用并换下一条或临时地址。
- 本地格式校验不承诺地址真实存在。
- 提交支付后结果未知时不得因为地址错误猜测而重复支付。

### 未来指纹

- 指纹按列表从上到下选择，不随机。
- 指纹采用软租约：优先让并发任务使用不同指纹。
- 指纹数量少于并发数时允许从顶部复用，不排队、不降低并发。
- 当前阶段不修改 `src/fprints.js`、浏览器或 Cloudflare 策略。
- 接入指纹池时必须修改 `src/network-context.js` 的 `effectiveImpersonation`，恢复对调用方指纹值的透传；该文件只在当前阶段保持不变，不是永久禁止修改。

### 本阶段必须预留的指纹入口

本阶段新增稳定的指纹提供器端口，但默认实现继续返回当前默认指纹，不改变线上 TLS 行为。任务调度器只依赖端口，不直接读取未来指纹库。

端口最小契约：

```js
provider.snapshot()
provider.acquire({ ownerId, ordinal })
provider.release(ownerId)
provider.publicView()
```

`acquire` 返回：

```js
{
  id,                 // 稳定且不含敏感内容的指纹 ID
  label,              // UI 脱敏名称
  impersonation,      // curl_cffi / TLS profile 名称
  userAgent,          // 可选
  headers,            // 可选、仅任务私下使用
  reused              // 是否因为软锁耗尽而复用
}
```

约束：

- `ordinal` 决定从上到下的稳定顺序。
- 优先返回当前未被其他任务使用的指纹。
- 全部正在使用时允许复用，不等待。
- 任务只公开 `id`、`label`、`reused`，不公开完整 headers 或客户端提示。
- 当前默认提供器可以只返回 `DEFAULT_IMPERSONATION`。
- 未来指纹库通过依赖注入替换提供器，不修改账号、卡、地址、代理和支付重试状态机。
- 接线模拟测试必须证明顺序选择、耗尽复用、任务快照和敏感字段不外泄。
- 完整契约见 `docs/fingerprint-provider-contract.md`。

## 原子资源包

每个账号任务需要：

```text
账号 + 代理（或直连）+ 卡 + 持久地址/临时地址 + 指纹
```

- 账号、代理、卡和持久地址必须全部取得后才能启动。
- 某个硬资源取得失败时立即释放本次已经取得的其他资源。
- 账号回到 FIFO 等待队列，等待资源释放事件。
- 不允许任务 A 持卡等待代理、任务 B 持代理等待卡。
- 临时地址和未来软指纹不构成排队条件。

## 支付阶段与故障切换

不可逆边界是任务记录 `confirm_started`。

### 提交支付前

- 代理连接失败：当前代理标记本批不可用，释放后换下一条代理重新开始该账号尝试。
- 卡格式错误、过期、CVC 错误或明确拒绝：本账号跳过该卡，换下一张；仅余额不足会持久暂停。
- 地址格式错误或平台明确拒绝：换下一条地址或生成临时地址。
- Cloudflare 未通过：当前阶段只记录明确错误类别，不修改 TLS/指纹轮换策略。

### 提交支付后

- 成功：更新账号套餐和金额，记录卡/地址成功次数，释放资源。
- 3DS：进入 `pending_3ds`，保留账号和卡租约，展示验证链接；首次 2 分钟后检查账号等级，之后每 25 秒检查。
- 明确未扣款失败：按错误类别安全释放或换资源。
- 网络异常、超时、Cloudflare 或其他模糊结果：进入 `unknown`，禁止自动重新提交。
- 3DS/unknown 的只读账号等级检查可以在原代理不可用时租用另一条健康代理，但不得调用支付确认接口。

## 错误决策表

| 错误 | 阶段 | 行为 |
|---|---|---|
| `insufficient_funds` | 明确未扣款 | 暂停当前卡，换下一张 |
| `expired_card` / `invalid_number` | 明确未扣款 | 标记卡无效，换下一张 |
| `incorrect_cvc` / `card_declined` | 明确未扣款 | 当前批跳过该卡，换下一张 |
| 地址本地校验失败 | 提交前 | 跳过地址，换下一条 |
| 平台明确地址错误 | 明确未扣款 | 本批跳过地址，重新创建尝试 |
| 代理连接失败 | 提交前 | 本批跳过代理，换下一条 |
| `pending_3ds` | 提交后 | 不换卡、不重复支付，等待等级变化 |
| `payment_result_unknown` | 提交后 | 只做状态协调，不重复支付 |
| CF 未通过 | 当前阶段 | 记录错误，不更改 TLS 策略 |

`authentication_required` 不是普通卡失败：有安全验证链接时进入
`pending_3ds`；缺少可验证链接时进入 `unknown`。两种情况都保留未决状态，
禁止自动换卡重扣。

## UI

- 代理弹窗按实际顺序显示序号。
- 显示最近测试状态和延迟，不显示密码。
- 批量任务区显示：代理预检中、可用数量、排队数量、处理中、3DS、未知、成功和失败。
- 资源等待不是失败，任务显示“等待可用资源”。
- 失败提示说明是否会自动换卡、换地址或换代理。
- 3DS 和未知结果继续使用现有详情弹窗，不在主界面堆叠敏感信息。
- 验证服务始终展开，代理与指纹接入口使用独立纵向卡片。
- 资源库主区只保留“导入 / 查看选择 / 清空”，不再保留第二套隐藏批量导入表单。
- 日志在新任务开始时自动刷新，并提供“清空当前日志”；持久任务记录另行按成功、失败或全部终态清理。

## 验证

只运行本地模拟测试，不访问 ChatGPT、Stripe 或真实代理：

1. 并发预检保持代理输入顺序，并跳过失败项。
2. 代理硬租约不允许并发重复。
3. 代理不足时账号排队，释放后从游标继续。
4. 无代理时全部任务走直连且不受代理数量限制。
5. 卡不足时账号排队，卡释放并冷却后继续。
6. 持久地址不足时生成互不重复的临时地址。
7. 资源包部分加锁失败会释放已取得资源。
8. 明确余额不足换卡，账号保持不变。
9. 提交前代理错误允许换代理。
10. `confirm_started` 后异常进入 unknown，不换卡、不重复提交。
11. 3DS 保留卡标签并只执行等级查询。
12. 公共 API、日志和 UI 不泄露代理密码。
13. 多个独立存储根目录之间的锁、游标和健康状态互不影响。
14. 默认指纹提供器不改变当前指纹行为。
15. 注入模拟指纹库后，任务按顺序选择、耗尽时复用且不降低并发。
16. 公共任务数据不暴露完整指纹 headers、UA 客户端提示或其他私有配置。
