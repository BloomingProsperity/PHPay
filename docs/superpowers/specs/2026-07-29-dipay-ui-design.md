# dipay 天空蓝白 UI 设计

## 目标

只重做 `public/index.html` 的展示与信息布局，不调整后端接口、请求参数、数据文件格式或支付逻辑。界面从当前的黑色纵向表单改为更宽松的桌面双栏工作台，降低首次进入时的信息密度。

## 视觉语言

- 页面背景为暖白与极浅天空蓝（`#f7fbff`、`#eef8ff`），不再使用深色界面。
- 主色为天空蓝（约 `#5bb8f5`），hover 使用更清亮的蓝色；文本采用深蓝灰，辅助文字为低对比蓝灰。
- 面板使用白色、细淡蓝边框、轻柔阴影和较大的圆角；不使用霓虹、高饱和渐变或厚重黑色边界。
- 危险操作保留克制的浅红提示，不和普通操作争夺视觉焦点。

## 信息架构

页面在宽屏使用约 65/35 的双栏，窄屏自动回落为单栏。

### 左侧：新建任务

1. 顶部用三枚紧凑统计卡表示账号、卡和地址库的数量。
2. 主任务卡优先展示账号输入、套餐选择、并发数以及执行按钮。
3. “仅生成链接”保持只依赖账号和套餐。
4. 卡与地址的手工填写、文件导入、批量粘贴、免税地址生成收进可展开的“支付资料（可选）”与资源库操作中；所有现有 DOM id 和事件绑定保留。
5. 批量支付作为独立的低强调危险操作，仍使用现有确认和接口。

### 右侧：资源和执行状态

1. 资源库固定展示账号、卡、地址三行；每一行包含数量、明确可见的「导入」按钮与「查看/选择」按钮。点击「导入」后，在该行下方展开原有的文件选择、批量粘贴和导入/清空控件；完成后自动收起并刷新数量。账号与卡的导入入口始终可见，不依赖主任务卡或折叠的支付资料。
2. 执行日志固定为右侧面板，包含进度条、状态标题、日志内容和生成的链接；无执行任务时显示简洁空状态。
3. 现有模态框继续用来选择库内条目与显示导入失败详情。

## 行为与兼容性

- 保留 `/api/accounts`、`/api/cards`、`/api/addresses`、导入/清空/生成接口与 SSE 执行流。
- 不改动任何支付、链接生成、批量处理、代理或浏览器相关逻辑。
- 保持键盘可用性、可见焦点和 `prefers-reduced-motion` 支持。
- 在 900px 以下切换为单栏，资源库与日志自然排到任务卡下方。

## 验证

- 在本地 Docker 页面检查宽屏与窄屏布局、淡蓝白视觉和所有原有控件可见性。
- 执行现有 `test/e2e.mjs`（若其依赖的本地服务可用），确认接口与页面事件没有回归。
- 使用浏览器检查默认页面和展开支付资料后的截图，确认日志、资源库、模态框未被遮挡。
